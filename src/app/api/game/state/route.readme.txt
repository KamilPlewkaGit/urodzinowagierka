File: `src/app/api/game/state/route.ts`

Purpose and responsibilities: Returns the current authenticated game snapshot used by lobby, admin, and active-game polling.

Important exports, inputs, and outputs: `GET(request)` requires an opaque current session and returns game, players, team scores, decimal total, Floor, SPORT, Melodia, and Pojedynki read models. A player receives only their own segment bet target, result, and payout.

Dependencies: `src/lib/database.ts` and `src/lib/session.ts`.

Backend/database interactions: Calls `getGameSnapshot` with the verified player ID when applicable, which reads game/segment state, roster, team scores, Floor duels, SPORT pairings/numbers/challenges/bonus requirements, Melodia songs/totals, Pojedynki slots, safe bet counts, and the viewer's own bets from Neon.

Implementation details: The `Cache-Control: no-store` header prevents browser/CDN caching from delaying state synchronization. Requiring a session lets a removed player receive a 401 on its next poll; the client then returns to the landing screen. The route returns no session secrets or mutation capability.

Future expansion: Add only safe spectator data to this contract; distinguish privileged fields with a separate authorized endpoint if needed.

Segment V exposes the five songs, current stage, team totals and leaders, final winner, settlement status, exact debit range, and the signed-in player's recorded balance change. The database reads the snapshot from a single consistent view.

Segment VI update: The snapshot now also includes four Pojedynki slots, their selected team sides/stages/winners, safe per-slot wager counts, and only the current player's own target/result/payout. It never exposes another bettor's identity or choice.

Segment VIII adds match summaries and the current Familiada board. The verified session role alone controls the privileged current answer key. The player projection contains only ranked slot placeholders and already published text and points, plus that player's own bet. The same no-cache poll synchronizes all phases.

For the active Floor duel, the snapshot includes category metadata, item count and the current live prompt. Embedded images use a dedicated URL, so the poll stays small.

The same verified administrator projection includes the current Floor answer. Player snapshots omit the field. Prompt and answer advance together in a single response.

The `finale` projection uses the shared poll for finalist qualification, question, estimate, direction, reveal, winner, wheel presentation and completion. Before reveal, only the verified administrator projection contains the current `adminAnswer` key.

The `alkoholicy` and `goldChallenge` projections synchronize the new stages, results and balances. Wager choices and nomination selections are scoped to the viewer. Only verified administrators see the aggregate nomination counts and live gold payout previews.
