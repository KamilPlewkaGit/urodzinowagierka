File: `src/app/lobby/page.tsx`

Purpose and responsibilities: Server-side entry gate for the waiting lobby. It verifies that the browser holds a player session, loads the current player and game snapshot, and redirects to the live screen if required.

Important exports, inputs, and outputs: `LobbyPage` accepts no props; it returns `LobbyClient` or issues a Next.js redirect to `/` or `/game`.

Dependencies: `src/lib/session.ts`, `src/lib/database.ts`, and `src/components/lobby-client.tsx`.

Backend/database interactions: Resolves the opaque cookie through `getCurrentSession`, then reads the player record and complete game snapshot from Neon.

Implementation details: `dynamic = "force-dynamic"` prevents stale route caching. The player record is rechecked in case a valid but orphaned session remains after database maintenance.

Future expansion: Keep access checks server-side. Add future lobby data to the snapshot/service rather than trusting a client route parameter.
