File: `src/lib/validation.ts`

Purpose and responsibilities: Defines server-side Zod schemas and nickname helpers for registration, administration, SOLENIZANT, The Floor, SPORT, Jaka to melodia?, and Pojedynki actions.

Important exports, inputs, and outputs: The Floor configuration accepts distinct `teamAId` and `teamBId`; bets accept `targetTeamId`; result confirmation accepts `winnerTeamId`. SPORT setup permits a pair-only confirmation with an empty rank list, or a complete ranking in which every submitted active player is ranked exactly once. Ranks are consecutive from 1 through the submitted team size and are not capped at five. SPORT bets, winners, four limb requirements, and bounded bonus points have focused schemas. All use the fixed team-ID schema.

Dependencies: Zod, team constants, and SOLENIZANT metadata.

Backend/database interactions: None. Route Handlers pass parsed data to `database.ts`.

Implementation details: SPORT validation rejects reused pair teams, duplicate ranks, duplicate player assignments, and gaps in a rank sequence before the database repeats authoritative stage, roster-membership, active-player, and full-roster checks. The bonus schema always carries all four stable teams.

Future expansion: Keep every sensitive endpoint on a narrow, focused schema.
